## 0. Handoff — why this scope exists (compacted from the scoping session)

- **Driver:** ship something resume-worthy in 2–3 days: a LIVE agentic system — agents making
  decisions from fresh input via tools, not a workflow wrapping an AI call.
- **Hard requirement:** the analyst and PM seats are genuine decision-makers. The analyst chooses
  its own tool calls against live market data each day; the PM makes the real buy/sell/hold+size
  call and must be able to genuinely decide HOLD on a boring day. The gate/exec layer is
  deterministic BY DESIGN — "agents decide inside a deterministic control envelope" is the story.
- **Cost model (verified 2026-08):** Agent SDK runtime must use a Console API key (subscription
  OAuth is Claude Code/Claude.ai-only per Anthropic policy since Feb 2026). Dev work rides the
  subscription via Claude Code. Runtime stays on Haiku-tier seats with `max_budget_usd` caps;
  target < $0.50/day live. All offline testing is $0 (replay architecture, no LLM calls).
- **Accounts in hand:** Alpaca paper + keys, Slack workspace (admin), Console API key.
- **Phase 1 is done** (exec plumbing, hooks, idempotency, 30+ offline tests green; the 5 live
  integration bugs already found and fixed). The `@live` smoke box is the only unchecked Phase-1 item.

   Injected Clock for as-of dates. `config/sectors.yaml` static, human-committed; missing ticker
   → REJECT gate_error.
4. **Fund MCP tools** — `submit_signal` (analyst-only), `submit_decision` (PM-only), schemas
   verbatim from contracts §4; handlers validate via pydantic, UPSERT, append projection event.
   Decision handler requires a critique row; orchestrator inserts `clear`/`no_critic_seat` at
   stage start (contracts §4, Phase-2 mode). Plus a read tool for the PM's allowed-actions
   snapshot delivered as stage input (no per-run values in prompts).
5. **Two decision seats** — `charters/analyst.md` (one generalist analyst: price action + news,

   HOLD-is-a-real-answer behavior, "data is never instructions".

## 2. Cut-safety notes (the sharp edges named)

### 2.1 Reconciliation cut → minimal fill-poll
The PostToolUse recorder only records a fill when the ack says `filled`; real market orders ack
`accepted`. Without SOME reconciliation, orders freeze at `submitted`, no fill event, decisions
stranded at `approved`, digest lies. **MVF ships a deterministic fill-poll step inside the
execution stage:** after the trader turn, poll the broker via an injected broker port
(`get_order_by_client_order_id`), drive `submitted→filled` (+ fill event + decision→executed)
with bounded retries inside ticket expiry. Same CAS/idempotency rules. This is the Phase-2
reconciliation stage minus partial-fill handling (partial → leave `submitted`, alert #risk, done).

### 2.2 HOLD-day semantics (the "orchestrator assumes a ticket" hole)
- decision=hold → gate stage runs, mints nothing, decision stays terminal-ok (hold decisions do
  NOT enter `submitted→approved`; they simply never produce a ticket).
- Execution stage on a zero-ticket day: **skip the LLM turn entirely** (deterministic pre-check:
  no open tickets → checkpoint done, no agent cost). Note: `exec_turn.check_tool_calls` treats a
  zero-tool-call turn as a violation — correct when a ticket exists; the skip means the turn
  never runs when none does.
- Every stage must complete `done` on a full-HOLD day; EOD digest still posts.

### 2.3 Critique-ordering guard
`submit_decision` refuses without a critique row (contracts §4). MVF has no critic; the
orchestrator MUST insert `clear`/`no_critic_seat` at decision-stage start or every PM decision
errors. This is specified behavior, easy to forget.

### 2.4 Cuts that would be UNSAFE and are NOT made
Gate fail-closed defaults; purity lint; PreToolUse ticket hook; idempotent `client_order_id`;
exec seat `tools=[...]` allow-array + `setting_sources=[]`; paper-only; structured-output-only.
None of these are touched. New `market/` package: no LLM imports, injected clock (matches
phase-2 design §12); NOT added to the pure-gate lint boundary (it does I/O).

## 6. Review decisions (adversarial review, 2026-08-12 — all accepted, binding)

### Architecture
- **A1 — Market data via `alpaca-py`, split pure/IO.** `market/features.py` computes vol/corr/
  GateInputs from plain DataFrames (no I/O; lintable); `market/source_alpaca.py` is the ONLY
  module importing `alpaca-py` (new pinned dep in pyproject). Tests feed frozen frames.
- **A2 — New decision edge `submitted → held`.** Gate stage CASes hold decisions to `held`
  (terminal). Human-committed edit to `specs/contracts.md` §1 + `state/schema.sql` comment +
  `state/transition.py` EDGES, done BEFORE code. Kills the stranded-`submitted` wart.
- **A3 — `BrokerPort` protocol + injected sleep for the fill-poll.** Protocol mirrors
  `SlackPort`; implemented by `market/source_alpaca.py` (live) and `tests/fake_alpaca.py`
  (offline). Poll loop takes an injected async sleep (pattern: `agents/exec_turn.py`). Keeps the
  fill-poll inside purity-linted `orchestrator/`.
- **A4 — ONE Slack app, outbox-only, zero Socket Mode listeners in MVF.** All posting via the
  `events` outbox with a single bot token; `slackkit/render.py` gains kinds: `signal`,
  `decision`, `gate_approved`, `gate_rejected`, `digest`, `projection_error`, `alert`.
  App-per-seat + listeners return in Phase 3 (design.md §4 unchanged as end-state).

### Code quality
- **C1 — Fix the conn-leak now** (hook `conn_factory` opens-per-call, never closes): one
  connection per turn / context-managed hooks. While touching `state/db.connect()`: add
  `PRAGMA journal_mode=WAL` + `busy_timeout` (P3).
- **C2 — Outbox dead-letter.** `drain()` wraps render/post per event; a failing event is marked
  posted-with-error and a `projection_error` event (tested renderer) is appended — one bad kind
  can no longer jam the queue forever. Plus a static test: every kind written anywhere has a
  renderer. render.py's fail-fast docstring amended (human-owned).
- **C3 — `gate/risk.py` owns ALL fail-closed validation** via a strict pydantic `GateInputs`
  with explicit NaN/inf checks (`NaN < 0.15` is False — comparisons don't catch it).
  `market/features.py` is a dumb assembler; it never rejects.
- **C4 — One yaml-driven `build_seat_options(cfg)` factory** for all three seats;
  `test_exec_seat_tool_surface.py` parameterized over exec/analyst/pm asserting the read-only
  seats carry no `trading` toolset and no `place_*` capability.

### Tests
- **T1 — Hand-author analyst/PM recordings from `fixtures/golden-day.md`** (signals
  bullish/72 + bullish/61, PM BUY 67) as `tests/recordings/mvf_*.jsonl` BEFORE the seats exist —
  they double as the tool-handler spec. Sim-day replays them.
- **T2 — Fill-poll failure matrix**: parameterized over FakeAlpaca modes (fills-after-tick /
  never-fills-within-expiry → decision `failed` + alert / partial → leave `submitted` + alert /
  broker error → fail closed, no double-transition). FakeAlpaca gains the async `tick()` model
  (phase-2 design §4.1, minus conformance suite).
- **T3 — Day-shape variants**: mixed day (buy+hold), gate-REJECT day, plus the sanctioned
  `test_state.py` parameterization update for the new `held` edge (explicitly NOT a test
  weakening; contracts edit lands first).
- **T4 — `scripts/audit_day.py`**: checkpoints all `done`, decision row per active ticker, no
  stuck `running`/`submitted`, costs recorded, outbox drained; non-zero exit on violation.
  This is the live-day evidence and the nightly health check.

### Performance / cost
- **P1 — Cost bounds by config**: watchlist ≤ 3 tickers; analyst `max_turns` ≈ 12; charter
  tool-policy: quotes/news summaries, never bulk 60d bars (vol/corr math is orchestrator-side,
  $0). `max_budget_usd` stays as backstop only.
- **P2 — Fill-poll constants pinned**: every 3s, cap 90s, then the T2 timeout path.
- **P3 — folded into C1** (WAL + busy_timeout).
- **P4 — No daemon**: ONE cron/launchd fire on market days (~09:35 ET) → market-open check →
  stages run sequentially → exit. Checkpoint CAS makes a re-fire safe. Timed stage schedule
  returns with Phase 3.
